# AI-Based Diabetes Prediction System

Academic minor project — supervised machine learning (Random Forest) for diabetes risk
prediction, with a responsive React + TypeScript web interface, a FastAPI service and a
complete, reproducible training pipeline.

## What is real in this project

- The model is a scikit-learn `RandomForestClassifier` trained by `backend/train_model.py`
  on a dataset built from the public **CDC NHANES 2013-2014** health survey.
- Every metric shown in the app (accuracy, precision, recall, F1, ROC-AUC, confusion matrix,
  feature importance) is read from `metrics.json`, produced by that training run.
- Predictions traverse the exported trees of the same trained forest with the same fitted
  preprocessing constants. Nothing is random or hardcoded.

## Project structure

```
backend/
  build_dataset.py            # NHANES download + dataset assembly -> data/diabetes_health.csv
  train_model.py              # cleaning, imputation, encoding, scaling, RF training, evaluation
  preprocessing.py            # reusable fitted preprocessing pipeline loader
  prediction.py               # model loading + prediction service
  visualize.py                # confusion matrix / ROC / importance / distribution figures
  main.py                     # FastAPI app: /predict, /health, /model-info, /metrics
  requirements.txt
  data/diabetes_health.csv    # generated dataset
  models/                     # diabetes_model.pkl, preprocessing_pipeline.pkl, metrics.json
  reports/                    # generated figures

src/
  ml/                         # model.json, metrics.json, analytics.json exported by training
  ml/inference.server.ts      # preprocessing + forest inference used by the web app
  lib/predict.functions.ts    # validated prediction server function
  routes/api/public/*.ts      # HTTP API mirror: predict, health, model-info, metrics
  routes/                     # Home, Prediction, Results, Dashboard, Model Performance,
                              # About, Documentation
  components/                 # header, footer, metric cards, workflow diagram, UI kit
```

## Running the Python backend

```bash
cd backend
pip install -r requirements.txt
python build_dataset.py     # downloads NHANES files and writes data/diabetes_health.csv
python train_model.py       # trains the model, writes models/* and src/ml/*
python visualize.py         # optional: writes report figures
uvicorn main:app --reload   # API docs at http://localhost:8000/docs
```

`python train_model.py` refreshes both the Python artefacts and the JSON files the web
application reads, so retraining automatically updates the dashboards.

### API

| Method | Endpoint      | Description                          |
| ------ | ------------- | ------------------------------------ |
| POST   | `/predict`    | Prediction for one patient record    |
| GET    | `/health`     | Service and model availability       |
| GET    | `/model-info` | Algorithm, features, hyperparameters |
| GET    | `/metrics`    | Evaluation metrics                   |

Example request:

```json
{
  "age": 52,
  "bmi": 31.4,
  "physical_activity": "Low",
  "blood_pressure": 138,
  "cholesterol": 215,
  "glucose": 142
}
```

The same contract is served by the deployed web app at `/api/public/predict`,
`/api/public/health`, `/api/public/model-info` and `/api/public/metrics`.

## Using your own dataset

Replace `backend/data/diabetes_health.csv` with a CSV containing the columns
`age, bmi, physical_activity, blood_pressure, cholesterol, glucose, diabetes`
and run `python train_model.py` again. All pages update from the new artefacts.

## Configuration

Copy `.env.example` to `backend/.env`. No secret keys are hardcoded in the codebase.
